02먼저 갖춰야 할 것

공통 컴포넌트

평면은 RealGridCommonJs.vue(GridView + LocalDataProvider), 계층이 필요하면 RealGridTreeJs.vue(TreeView + LocalTreeDataProvider)를 쓴다. 계층이 필요한데 평면 컴포넌트를 쓰면 부모·자식이 안 나오니, 그때는 반드시 트리 쪽을 가져가야 한다. 컴포넌트 자체는 수정할 필요가 없다 — 페이지에서 props와 @init으로만 제어한다.

페이지 <script>

import { showToast } from '@/utils/toastUtil.js'   // 없으면 아무 토스트로 교체

@init에서 받아 보관하는 두 개

아래 모든 코드가 이 두 개를 전제로 한다. 반응형으로 만들지 말 것 — data()에 넣으면 Vue가 RealGrid 내부까지 프록시로 감싸서 오작동한다.

}

04블록이 재지정돼 보이던 문제

여러 행을 블록으로 선택한 뒤 그 안쪽을 잡고 끌면, 옮겨지는 행은 처음 블록 그대로인데 화면에서는 블록이 포인터를 따라 계속 다시 그어졌다. 커밋 ea9164f에서 잡은 문제다.

원인은 이벤트 순서 하나

RealGrid는 셀 선택을 mousedown이 아니라 pointerdown에서 처리한다. 브라우저는 마우스를 한 번 누르면 pointerdown → mousedown 순으로 이벤트를 내므로, mousedown에 도달한 시점에는 이미 늦다.

3~5행을 블록 선택해둔 상태에서 그 안(4행)을 눌러 각 시점의 그리드 상태를 찍은 실측값:

1. pointerdown CAPTURE | current.dataRow=3 | selectedRows=[3,4,5] 2. pointerdown bubble | current.dataRow=4 | selectedRows=[4] 3. mousedown CAPTURE | current.dataRow=4 | selectedRows=[3,4,5]

①에서 current.dataRow가 아직 3이다 — 사용자는 4행을 눌렀지만 RealGrid가 처리 전이라 직전 커서가 남아 있다. ②에서 앵커는 4로 정확해졌지만 그 대가로 블록이 [4]로 접혔다. ③의 [3,4,5]는 우리 핸들러가 이미 복원한 결과다.

필요한 두 정보가 서로 다른 순간에만 존재한다. 누르기 직전의 블록은 ①에서만, 실제로 누른 행(앵커)은 ②부터. 그래서 핸들러가 두 개다 — ①은 기억만 하고, 판정은 mousedown에서 한다.

capture가 필수인 이유

이벤트는 캡처(바깥→안쪽) → 타깃 → 버블(안쪽→바깥) 순으로 흐른다. 래퍼는 RealGrid 셀의 조상이므로, 캡처로 붙여야 RealGrid보다 먼저 받는다. 기본값인 버블로 붙이면 ②를 받게 되고 — 블록은 이미 사라진 뒤다.

@pointerdown.capture는 Vue가 만든 이벤트가 아니라 addEventListener('pointerdown', fn, { capture: true })의 축약이다. pointerdown은 W3C Pointer Events 표준이고 PointerEvent는 MouseEvent를 상속한다.

mousedown 쪽 .capture는 현재 기준으로는 없어도 동작한다. pointerdown이 통째로 먼저 끝나므로 어느 단계든 RealGrid 처리는 이미 완료다. 남겨둔 이유는 두 핸들러의 단계를 맞춰 순서를 예측 가능하게 두는 것과, RealGrid가 나중에 셀에서 stopPropagation()을 부르면 버블 핸들러는 아예 안 불리기 때문이다.

05해결: 네 단계

아래 파이프라인이 엔진 전체다. 파란 줄이 우리 코드가 끼어드는 지점.

·

③

움직임마다 블록을 원래대로 되돌린다(keepBlockSelection). 드래그 시작 판정은 여기 — 5px이 아니라 그리드를 벗어났는가로.

끌었으면 드롭 처리, 안 끌었으면 눌린 행 하나로 접고 그때의 블록을 기억한다.

① 스냅샷 — 판단하지 않는다

onGridPointerDown(e) {
  if (e.button !== 0 || !this.gridView) return
  this._prePress = {
    rows: this.snapshotSelectedRows(),
    selection: this.snapshotSelection()
  }
}

snapshotSelection()이 getSelection() 결과를 그대로 들고 있지 않고 순수 값으로 복사하는 게 중요하다. RealGrid는 그 객체를 계속 고쳐 쓴다. 

snapshotSelection() {
  const sel = this.gridView.getSelection()
  if (!sel || sel.startItem == null) return null
  return {                       // 참조로 들고 있으면 안 된다
    cellType: sel.cellType, style: sel.style,
    startItem: sel.startItem, startColumn: sel.startColumn,
    endItem: sel.endItem, endColumn: sel.endColumn
  }
}

② 판정과 동결

const cur = this.gridView.getCurrent()
const anchor = (cur && cur.itemIndex >= 0)
  ? { itemIndex: cur.itemIndex, dataRow: cur.dataRow, column: cur.column } : null

// 여러 행이 선택돼 있었고(①), 그 블록 안쪽을 눌렀다(②) = 옮기려는 제스처
const canFreeze = !!(anchor && anchor.dataRow >= 0 &&
  preSelectedRows.length > 1 && pre.selection &&
  preSelectedRows.includes(anchor.dataRow))

if (canFreeze) {
  this.gridView.setSelection(pre.selection, false)   // 접힌 걸 되돌리고
  this.releaseGridPointer(e)                        // 추적을 끊고
  this.isBlockDrag = true
}

pointerdown과 mousedown 사이에는 리페인트가 없다. 그래서 접혔다가 되돌아온 게 화면에 안 보인다 — 깜빡임 없이 블록이 고정된 것처럼 보이는 이유다.

합성 이벤트로 추적 끊기

releaseGridPointer(e) {
  const base = { bubbles: true, cancelable: true,
    clientX: e.clientX, clientY: e.clientY, button: 0, buttons: 0 }

  const pointerUp = new PointerEvent('pointerup',
    { ...base, pointerId: 1, pointerType: 'mouse' })
  pointerUp.__nexhubSynthetic = true     // 우리가 되받지 않도록 표시
  e.target.dispatchEvent(pointerUp)

  const mouseUp = new MouseEvent('mouseup', base)
  mouseUp.__nexhubSynthetic = true
  e.target.dispatchEvent(mouseUp)
}

표시해서 보낸 이벤트는 onDocMouseUp 첫 줄에서 걸러진다. if (e && e.__nexhubSynthetic) return — 이 한 줄을 빠뜨리면 드래그가 즉시 종료된다.

③ 그래도 다시 긋는다 — 움직임마다 되돌리기

keepBlockSelection() {
  const frozen = this._press && this._press.blockSelection
  if (!frozen || !this.gridView) return
  const cur = this.gridView.getSelection()
  if (cur && cur.startItem === frozen.startItem && cur.endItem === frozen.endItem &&
      cur.startColumn === frozen.startColumn && cur.endColumn === frozen.endColumn) return
  this.gridView.setSelection(frozen, false)
}

합성 pointerup만으로는 그리드 안쪽 움직임까지 끊지 못한다. 이 핸들러는 window 버블이라 그리드 자신의 갱신 뒤에 돌고, 그 사이 화면을 다시 그리지 않으므로 사용자 눈에는 처음부터 고정돼 보인다.

③ 드래그 시작 조건 — 거리가 아니라 경계

const rect = this._press.gridRect
const isPointerOutsideRight = e.clientX > rect.right - 10
const isOverZone = this.checkIsOverDropZone(e.clientX, e.clientY)

// 그리드 '안'에서의 움직임은 RealGrid의 블록 선택이다. 가로채면 안 된다.
if (!this._press.moveGesture && !isPointerOutsideRight && !isOverZone) return

여기를 dist > 15 같은 거리 조건으로 두면 기능이 깨진다

사용자가 행을 훑어 블록을 그리는 제스처를 드래그로 가로채게 된다. 그러면 mouseup이 "드래그였다"로 처리되어 블록을 기억하는 경로가 통째로 건너뛰어지고, 결과적으로 블록 이동이 아예 안 된다. 예외는 moveGesture 하나 — ②에서 이미 RealGrid의 선택 추적을 끊었으니 경쟁 상대가 없다.

④ 끌지 않았을 때

if (!wasDragging) {
  // 블록 안을 그냥 클릭했다 = 그 행 하나만 고르려는 의도
  if (press && press.moveGesture && press.anchor) this.collapseSelectionTo(press.anchor)
  this.rememberBlockFromGrid()    // 이때의 선택만 블록으로 기억한다
  return
}
this.finishDrag(e)

블록 기억을 선택 이벤트로 갱신하지 않는 것이 핵심이다. 누르고 있는 동안에는 RealGrid가 선택을 계속 바꾸고, 그 통보가 우리 드래그 시작보다 먼저 올지 나중에 올지 정해져 있지 않다. 그래서 onSelectionEnded는 이렇게 막는다. 

gridView.onSelectionEnded = () => {
  if (this._press) return        // 누르는 중이면 무시. 키보드 선택만 통과
  this.rememberBlockFromGrid()
}

06블록 = 체크

규칙은 하나다. 체크 상태 = 지금 화면의 블록. 화면에 블록이 없는데 체크만 남아 있으면 무엇이 배정될지 화면만 보고는 알 수 없다.

새 이벤트를 만들 필요가 없다. rememberBlockFromGrid()가 이미 마우스 블록과 키보드 Shift 선택이 함께 합류하는 "선택 제스처가 끝난 시점"이다. 

rememberBlockFromGrid() {
  const selected = this.snapshotSelectedRows()
  this._blockRows = selected.length > 1 ? selected : []

  // 체크바를 누른 제스처인가. (onGridPointerDown 에서 위치로 판별해 둔 값)
  const viaCheckbar = this._pressOnCheckbar

  // 블록을 씌웠다 = 그 안의 모델이 고른 것
  if (selected.length > 1) {
    this.syncChecksToBlock(selected)
    return
  }

  // 블록이 사라졌다 = 고른 게 없다. 체크도 비운다.
  if (viaCheckbar) return
  this.clearAllChecks()
}

규칙 셋

  • 블록을 그으면 그 안의 모델만 체크되고 이전 블록의 체크는 지워진다. checkAll의 두 번째 인자를 false로 줘야 접혀 있는 카테고리 안의 체크까지 해제된다.
  • 블록이 사라지면(블록 밖 클릭 등) 체크도 같이 비운다.
  • 예외는 체크바 직접 클릭. 그것도 '한 행 선택'이라 그냥 지우면 수동 체크가 아예 불가능해진다.

체크바 클릭은 이벤트 순서로 구분할 수 없다

RealGrid의 체크 토글(onItemChecked)은 우리 mouseup보다 뒤에 온다. 그래서 "체크 이벤트가 왔으면 지우지 않는다"로 짜면 그 사이에 이미 지워진 뒤라, 방금 켜진 체크가 사라진다. 누른 위치로 판별해야 한다. 

isCheckbarPoint(x, y) {
  const el = document.elementFromPoint(x, y)
  return !!(el && el.closest('[class*="rg-checkbar"]'))
}

onGridPointerDown에서 this._pressOnCheckbar = this.isCheckbarPoint(e.clientX, e.clientY)로 한 번 재둔다.

rememberBlockFromGrid는 한 제스처에 두 번 불린다

onDocMouseUp과 onSelectionEnded 양쪽에서 온다. 그래서 위 표시를 이 함수 안에서 소비(리셋)하면 안 된다 — 첫 호출이 소비해 버리면 두 번째 호출이 방금 켜진 체크를 지운다. 표시를 내리는 곳은 제스처 시작 한 군데뿐이다.

07트리에 얹을 때 — 계층 함정 넷

평면 그리드에는 없는 문제다. 에러가 안 나고 조용히 틀리는 것들이라 미리 알고 가는 게 싸다.

현재 tree-to-div 페이지의 배정 단위는 부모(그룹)다. 자식은 좌측에 아예 그리지 않고, 부모를 옮기면 소속으로 자식이 따라온다. 잎을 옮기던 예전 판과 정책만 다르고 엔진은 그대로다 — 바뀌는 곳은 09장의 변환 함수 하나다.

children 키는 "자식 배열"이 아니라 "자식 있음" 표시다

setNestedRows의 childrenProp은 빈 배열도 "자식 있음"으로 읽는다. 그래서 잎을 그릴 때는 키 자체를 넣지 않아야 화살표 자리가 비고, 부모만 다루는 화면(현재 tree-to-div)이라면 rows에 children을 아예 넣지 않는다 — 그래야 “자식은 숨긴다”가 성립한다. 

// 잘못  { modelName: '...', children: [] }
// 맞음  { modelName: '...' }

트리의 getCheckedRows는 인자 의미가 다르다

GridBase는 getCheckedRows(sort, visibleOnly, allRows)지만 TreeView는 getCheckedRows(visibleOnly)다. 접혀 있는 노드까지 포함하려면 false를 넘겨야 한다. 

this.gridView.getCheckedRows(false)   // visibleOnly = false

배정 대상이 아닌 행은 checkableCallback으로 뺀다

공통 컴포넌트가 설정한 체크바를 @init에서 덮어쓴다. 나머지 옵션도 같이 넘겨야 유실되지 않는다. checkAll과 헤더 전체체크도 이 콜백을 존중한다. 

gridView.setCheckBar({
  visible: true, width: 34, exclusive: false, head: 'check',
  checkableCallback: (dataSource, item) => {
    const info = this.nodeInfo(item && item.dataRow)
    return !!(info && info.nodeType === 'category')   // ← 정책. 잎만 옮기던 판에서는 'model'
  }
})

체크바는 2상태뿐이라 ‘일부만 체크’를 표현하지 못한다. 배정 단위가 아닌 행은 체크 자체를 막아야 “고른 것 = 체크된 것”이 화면과 어긋나지 않는다.

트리 provider의 getJsonRow는 기본이 재귀다

하위까지 통째로 묶어 준다. 한 행의 값만 필요하면 재귀를 명시적으로 꺼야 한다. 

nodeInfo(dataRow) {
  if (!this.dataProvider || dataRow == null || dataRow < 0) return null
  try { return this.dataProvider.getJsonRow(dataRow, false, false) || null }
  catch (e) { return null }
}

09갈아끼울 곳은 넷

엔진이 도메인을 만나는 접점은 이게 전부다. 평면과 트리가 갈라지는 곳도 여기 하나뿐이다.

훅계약부르는 곳
rowsToXxx(rows)dataRow 배열 → 도메인 값 배열. 대상 아닌 행은 여기서 걸러낸다onDocMouseMove · checkedXxx
assignXxx(값들)실제 이동. 성공 개수 반환finishDrag · assignChecked
createGhost(값들)따라다니는 라벨 문구onDocMouseMove
nodeInfo(dataRow)(계층 전용) 행 → 노드 객체. 배정 단위 판별 필드 포함변환 · 체크바 콜백

계층 해석을 변환 함수 한 곳에 몰아두는 게 요령이다. 드래그·체크·블록 혼합이 모두 이 함수로 합류하므로, “잎만” 이든 “부모만” 이든 “부모는 하위 전체로 펼침” 이든 정책을 여기서만 바꾸면 된다. 중복은 Set으로 거른다.

평면 — 행을 그대로 옮긴다 (grid-to-div)

변환이랄 게 없다. 드래그로 확정한 dataRow 배열을 그대로 넘긴다.

assignRows(rows) {
  if (!rows || !rows.length) return
  const items = rows.map(r => this.dataProvider.getJsonRow(r)).filter(Boolean)
  if (!items.length) return

  this.groupModels.push(...items)      // 우측 목록
  this.dataProvider.removeRows(rows)   // 좌측에서 제거
  // ... 대표 지정 · 토스트 · 선택/체크 정리
}

계층 — 배정 단위로 접어서 넘긴다 (tree-to-div · 현재 부모 단위)

rowsToCategoryNames(dataRows) {
  const names = []
  const seen = new Set()
  ;(dataRows || []).forEach(row => {
    const info = this.nodeInfo(row)
    if (!info || info.nodeType !== 'category' || !info.category) return   // ← 정책
    if (seen.has(info.category)) return
    seen.add(info.category)
    names.push(info.category)
  })
  return names
}

잎(모델)을 옮기는 화면이라면 조건을 nodeType !== 'model', 값은 info.modelId로 바꾸면 그대로 돈다. 부모를 하위 전체로 펼치고 싶으면 이 함수 안에서 자식을 훑어 넣는다 — 다른 곳은 손대지 않는다.

좌측 목록을 어떻게 되돌릴지(우측 X)는 이 문서 범위 밖이다. realtree-배정-원복-가이드를 함께 볼 것.
