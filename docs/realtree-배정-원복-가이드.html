배정 목록 X(원복) 구현 가이드

우측 배정 목록에서 X를 눌러 하나를 빼면, 좌측 그리드·트리로 정확히 그 하나만 돌아와야 한다. 말은 한 줄인데 옮겨 심으면 거의 반드시 두 가지가 깨진다 — 왜 깨지고, 어떤 구조가 안 깨지는가.

원본 ① RealGridTreeToDivPage.vue (트리 · 권장) 원본 ② RealGridToDivGuidePage.vue (평면) Vue 3 Options API

01깨지는 두 가지

증상보이는 것원인 표
A · 원복 안 됨 X를 눌렀는데 좌측에 다시 안 나타난다. 우측에서만 사라지고 그대로 끝. 05
B · 전부 사라짐 하나만 지웠는데 우측 목록이 통째로 비거나 엉뚱한 항목까지 함께 사라진다. 06
한 줄 규칙 — 우측 배정 목록이 원본이고, 좌측은 그 결과로 파생되는 화면이다. 되돌리기가 깨지는 구현은 예외 없이 이 관계가 뒤집혀 있거나, 좌우가 각자 자기 데이터를 들고 서로를 모른다. 그러면 “우측에서 빼기”와 “좌측에 넣기”가 별개 작업이 되고, 둘 중 하나만 성공하는 순간 증상 A가 난다.

02권장 구조 — 좌측을 computed로 파생

상태는 두 개뿐이다. 전체 원본과, 우측으로 옮긴 것들의 목록. 좌측은 둘의 차집합이므로 되돌리는 코드가 따로 없다.

RealGridTreeToDivPage.vue 
data() {
  return {
    catalog: [],             // 전체 원본(평면). 배정/원복으로 절대 변하지 않는다
    assignedCategories: []   // 우측으로 옮긴 것 (모델 단위면 modelId 배열)
  }
},
computed: {
  assignedSet() { return new Set(this.assignedCategories) },

  // 좌측 = 전체 − 배정됨
  poolCategories() {
    return CATEGORY_DEFS.filter(cat => !this.assignedSet.has(cat.name) && this.modelsByCategory.get(cat.name).length)
  },

  // 트리 rows 는 매번 통째로 다시 만든다
  treeRows() {
    return this.poolCategories.map(cat => ({ nodeType: 'category', category: cat.name, /* ... */ }))
  }
}

되돌리기는 이게 전부다.

returnCategory(name) {
  const idx = this.assignedCategories.indexOf(name)
  if (idx < 0) return
  this.assignedCategories.splice(idx, 1)   // ← 두 번째 인자 1 (06-1)

  if (this.openedCategory === name) this.openedCategory = null  // 열려 있던 팝업 닫기
  this.syncRepresentatives()   // 그룹별 대표 모델 승계
  this.syncRepCategory()       // 대표 그룹(우측 라디오) 승계
  this.resetCheckState()       // 트리를 다시 그리면 체크는 사라진다 → 카운트도 초기화
}

RealGridTreeJs는 rows prop을 deep watch해 setTreeRows()를 다시 부른다. treeRows가 바뀌면 좌측은 알아서 복구된다. RealGrid 노드를 직접 지우고 붙이지 않는 것이 핵심이다 — 트리에서 그렇게 하면 부모가 빈 채로 남거나 dataRow 인덱스가 어긋나는데, 통째로 다시 만들면 그 경우의 수가 아예 없다.

성능 걱정은 나중이다. 재구성은 배정·원복이 일어날 때만 돈다. 사람이 클릭하는 빈도로는 수천 행에서도 문제가 되지 않는다.

03대안 구조 — provider 직접 조작 (평면 전용)

계층이 없는 평면 그리드라면 dataProvider를 직접 만져도 안전하다. 트리에서는 쓰지 않는다.

RealGridToDivGuidePage.vue 
returnToGrid(modelId) {
  const idx = this.groupModels.findIndex(m => m.modelId === modelId)
  if (idx < 0) return
  const item = this.groupModels.splice(idx, 1)[0]   // 뺀 '그 객체'를 그대로 되돌린다
  if (!item) return

  if (this.repModelId === item.modelId) {              // 대표였으면 승계
    this.repModelId = this.groupModels.length > 0 ? this.groupModels[0].modelId : null
  }

  this.dataProvider.addRow(item)                     // ← 이 한 줄 누락이 증상 A의 1순위
  this.syncPoolCount()
  this.syncCheckedCount()
}
규칙이유
뺀 객체를 그대로 다시 만들면 필드가 빠지거나 타입이 달라져 좌측에서 빈 행처럼 보인다.
카운트 재계산 provider를 직접 만지면 화면 숫자는 자동으로 따라오지 않는다.
트리에는 금지 되돌린 행을 어느 부모 밑에 넣을지 매번 계산해야 하고, 부모가 이미 지워졌으면 붙을 곳이 없다.

04X 버튼의 이벤트 계약

카드 전체가 클릭 대상(팝업 열기·대표 선택)인 경우가 많다. X는 반드시 전파를 끊어야 한다. 

<!-- 카드 전체 = 팝업 열기 -->
<div class="div-dropped-item" role="button" tabindex="0" @click="openCategoryPopup(group.category)">

  <!-- 라디오도 카드 클릭으로 번지면 안 된다 -->
  <input type="radio" class="rep-radio" @click.stop @change="setRepCategory(group.category)" />

  <span class="item-main">...</span>

  <!-- X: 카드 클릭까지 발동하면 '지웠는데 팝업이 뜨는' 동작이 된다 -->
  <button class="btn-return-grid" @click.stop="returnCategory(group.category)">
    <i class="bi bi-x-lg"></i>
  </button>
</div>
  • 카드가 <label>이면 @click.prevent.stop. prevent가 없으면 라벨 클릭이 내부 라디오를 토글한다.
  • 드래그로 카드 위에 드롭한 직후의 click도 막는다 — finishDrag에서 한 틱만 _suppressCardClick을 세운다.

05증상 A · 좌측에 안 돌아온다

원인확인법고침
addRow 누락 provider 조작 방식인데 우측 배열 길이만 줄어든다. 02장 구조로 바꾸거나 addRow 추가
rows가 고정 좌측 rows가 computed가 아니라 data다. 좌측을 상태에서 파생시킨다
제자리 수정 rows를 push/splice만 하는데 watch가 얕다. 새 배열로 교체하거나 deep watch
부모 증발 마지막 자식을 옮긴 뒤 트리에서 부모 행이 사라졌다. 트리는 03장 방식 금지 → 02장
원본 훼손 배정할 때 catalog.splice(...)로 원본에서 지운다. 원본은 불변. ‘배정됨’ 목록만 따로 관리

06증상 B · 하나 지웠는데 다 사라진다

1 · splice 두 번째 인자 누락

가장 흔하다. 인자가 하나면 그 뒤가 전부 잘린다.

arr.splice(idx)      // ✗ idx부터 끝까지 삭제
arr.splice(idx, 1)   // ✓ 하나만

2 · v-for의 key를 인덱스로

중간을 지우면 뒤 항목들의 key가 밀려, Vue가 남길 DOM과 지울 DOM을 잘못 고른다.

<div v-for="(item, i) in list" :key="i">        // ✗
<div v-for="item in list" :key="item.modelId">  // ✓ 안정적인 식별자

3 · 삭제 조건이 분류·그룹 기준

같은 카테고리의 형제들이 통째로 날아간다.

list.filter(m => m.category !== item.category)  // ✗
list.filter(m => m.modelId !== id)             // ✓ 항상 고유 id 비교

4 · 좌우가 같은 배열 인스턴스를 공유

한쪽에서 지우면 다른 쪽도 같이 비워진다. 목록은 항상 새 배열로 만들어 넘긴다.

5 · 좌우 필터 조건이 한쪽에서 뒤집힘

has와 !has를 각각 다른 파일에 복붙해 두면 언젠가 한쪽만 고친다. 판정은 한 곳에서만 정의한다.

07되돌린 뒤 남는 잔여물

증상원인고침
라디오 꺼짐 지운 항목이 대표였는데 승계를 안 했다. “없으면 남은 첫 번째” 규칙을 한 함수에 모은다
체크 수 남음 그리드 체크는 사라졌는데 페이지 카운트만 남았다. resetCheckState()로 카운트·블록 기억까지
유령 팝업 팝업 대상이 사라졌는데 상태만 남았다. 지운 이름이 열린 대상이면 null
not exists column 저장된 레이아웃이 사라진 컬럼을 참조한다. 컬럼을 바꿨으면 grid-id를 올린다

08부모(그룹) 단위로 옮길 때

자식은 숨기고 부모만 옮기는 화면에서는 자식을 복사해 들고 다니지 않는다. 

// 우측에는 부모 이름만 쌓는다. 자식은 소속으로 언제든 다시 묶인다
assignedCategories: ['센서/전자', ...]

assignedGroups() {
  return this.assignedCategories.map(name => ({
    category: name,
    models: this.modelsByCategory.get(name) || []   // ← 파생
  }))
}

되돌리기가 이름 하나 빼는 일이 된다. 모델이 추가돼도 자식 수가 저절로 맞는다. 자식 배열을 우측에 복사해 두면 “부모는 돌아왔는데 자식은 옛날 것”이 된다.

09이식 후 5분 점검

순서대로 해 보고 하나라도 어긋나면 05·06의 표에서 원인을 찾는다.

  1. 013개를 우측으로 옮긴다좌측에서 정확히 3개가 사라진다
  2. 02가운데 것 X그것만 좌측 원래 자리(정렬·부모 밑)에 돌아오고 우측에 2개가 남는다
  3. 03대표였던 것 X라디오가 남은 항목으로 옮겨 붙는다
  4. 04마지막 하나 X우측은 빈 안내로, 좌측은 처음 상태와 개수·순서까지 동일
  5. 05X를 눌러도 카드 클릭(팝업·선택)이 함께 발동하지 않는다
  6. 06되돌린 항목을 다시 옮긴다중복 없이 한 번만 들어간다
  7. 07[전체 초기화]좌측이 초기 상태와 완전히 동일

10AI에게 그대로 주는 규칙

이식을 지시할 때 아래 블록을 프롬프트에 붙인다.

배정 목록의 X(되돌리기)를 구현할 때 지킬 것 1. 우측 배정 목록만 상태로 들고, 좌측 목록/트리 rows 는 "전체 − 배정됨" computed 로 파생시켜라. 좌측 rows 를 직접 지우거나 넣지 마라. 특히 트리(RealGrid TreeView)에서는 절대 금지. 2. 되돌리기는 "배정 배열에서 그 항목 하나 빼기"로 끝나야 한다. arr.splice(idx, 1) — 두 번째 인자 1 필수. 3. v-for 의 :key 는 인덱스가 아니라 항목의 고유 id. 4. 삭제 조건은 항상 고유 id 비교다. 분류/그룹/이름 기준으로 filter 하지 마라. 5. 원본 전체 목록(catalog)은 배정/원복으로 변경하지 않는다. 6. 지운 항목이 대표(라디오)였다면 남은 첫 항목으로 승계하고, 목록이 비면 대표를 null 로. 이 규칙은 배정·원복·초기화가 모두 같은 함수를 부르도록 한 곳에 모은다. 7. X 버튼은 @click.stop (label 안이면 @click.prevent.stop) 으로 카드 클릭과 분리한다. 8. 되돌린 뒤 체크 카운트·블록 기억·열린 팝업 상태를 함께 정리한다. 9. 컬럼 구성을 바꿨다면 저장된 레이아웃 충돌을 피하려 grid-id 를 올린다. 검증 3개 배정 → 가운데 X → 좌측에 그것만 복귀, 우측 2개 유지 → 대표 X → 라디오 승계 → 마지막 X → 양쪽 모두 초기 상태. 이 시나리오가 통과해야 완료다.
