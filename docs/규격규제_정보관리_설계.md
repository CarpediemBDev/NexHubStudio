## 1. 도메인 - 한국에서 TV를 팔려면 뭐가 걸리나

TV 1대를 국내에 출시할 때 실제로 붙는 규제는 크게 6갈래다. 이게 곧 화면의 **분야(FIELD)** 코드가 된다.

| 분야 | 규제(법령) | 규격/기준 | 마크·표시 | 소관 |
|---|---|---|---|---|
| 안전 | 전기용품 및 생활용품 안전관리법 — **안전확인** | KC 62368-1 (AV·ICT 기기 안전) | KC 마크 + 안전확인신고번호 | 국가기술표준원 |
| 전자파(EMC) | 전파법 — 방송통신기자재 **적합등록** | KN 32(방사), KN 35(내성) | KC 마크 + 적합성평가 식별부호 | 국립전파연구원 |
| 무선(RF) | 전파법 — 무선설비 **적합인증** | 무선설비규칙(Wi-Fi/BT 기술기준) | KC 마크 + 식별부호 | 국립전파연구원 |
| 에너지 | 에너지이용 합리화법 — **효율관리기자재** | 효율관리기자재 운용규정 [별표] 텔레비전수상기 | 에너지소비효율등급 라벨(1~5등급) | 한국에너지공단 |
| 에너지 | 에너지이용 합리화법 — **대기전력저감프로그램** | 대기전력저감 운용규정 | 에너지절약마크 / 대기전력 경고표지 | 한국에너지공단 |
| 환경/유해물질 | 전기·전자제품 및 자동차의 자원순환에 관한 법률 — **K-RoHS** | 유해물질 6종(Pb·Cd·Hg·Cr6+·PBB·PBDE) 제한 | 없음(자료 보관) | 환경부 |
| 자원순환 | 자원순환법 — **EPR 생산자책임재활용** | 재활용의무율 고시 | 없음(분담금 납부) | 전자제품자원순환공제조합 |
| 표시/라벨 | 자원재활용법 — 분리배출 표시 | 분리배출 표시 지침 | 분리배출 마크 | 환경부 |
| 표시/라벨 | 제품 표시·광고 규정 | 전기용품 한글 표시사항 | 한글 표시 라벨 | 국표원 / 공정위 |
| 방송/통신 | 방송법 / 지상파 UHD | ATSC 3.0, TTA 표준 (튜너·자막·재난경보) | — | 과기정통부 / TTA |
| 화학물질 | 화학물질등록평가법(K-REACH) | 등록·신고 대상 물질 | — | 환경부 |

> 실무 포인트: **KC 마크는 하나가 아니다.** 안전확인(국표원)과 적합성평가(전파연구원)가 각각 KC 마크를 요구하고, 번호 체계와 소관 기관이 다르다.
> 그래서 마스터 1행 = 인증 1건으로 쪼개야 하고, "TV = KC" 식으로 뭉치면 안 된다.

같은 TV를 유럽에 팔면 CE(LVD·EMC·RoHS·에너지라벨/EPREL) 로 통째로 갈아끼워야 하는데,
**여기서 권역 vs 국가 충돌이 발생한다.** (아래 3장)

## 2. 테이블 4개

```
REG_INFO (정보 레코드)
   │ 1
   ├──< REG_INFO_TARGET  (규제·규격·사업부·제품군·제품·권역·국가 = 멀티셀렉트)
   ├──< REG_INFO_HIST    (수정 = 새 VERSION INSERT + 스냅샷)
   └──< REG_CONFLICT_HIST(저장 직전 판정 결과 + 담당자 조치)
```

### 2-1. REG_INFO — 단일 값만
제목, **분야**, 인증마크, 소관기관, **URL**, 요약, 상태, 버전, 시행일.
분야는 멀티가 아니라서 마스터에 둔다(충돌 판정의 1차 필터로도 쓴다).

**첨부는 별도 테이블을 안 만든다.** 이 프로젝트엔 이미 파일 관리 모듈이 있으니
`ATTACH_GROUP_ID` 하나로 연계한다 → 테이블 4개 유지.

### 2-2. REG_INFO_TARGET — 멀티셀렉트 7종을 한 테이블에
`TARGET_TYPE` 으로 7종을 수용한다. 핵심은 **`LEVEL_NO`** 다. 충돌 판정이 이 값을 본다.

| 축 | 계층 |
|---|---|
| GEO | 권역(1) > 국가(2) |
| ORG | 사업부(1) > 제품군(2) > 제품(3) |
| RULE | 규제(1) > 규격(2) |

`EXCLUDE_YN='Y'` 는 충돌 조치 `EXCLUDE` 의 결과다 — "유럽 전체, 단 프랑스 제외"를 한 레코드로 표현한다.

### 2-3. REG_INFO_HIST — 스냅샷 방식
타겟이 멀티행이라 컬럼 diff 만으로는 과거 버전을 복원할 수 없다.
그래서 마스터+타겟 전체를 `SNAPSHOT_JSON` 에 담는다. (메일 템플릿 버전 관리와 동일한 전략)

### 2-4. REG_CONFLICT_HIST — 판정과 조치를 같이
`CONFLICT_TYPE`, `CONFLICT_AXIS`, 양쪽 범위 텍스트, `DECISION_CD`, 판정/조치 일시.
등록을 취소해도 행을 남긴다(`STATUS_CD='IGNORED'`, `NEW_REG_INFO_ID=NULL`) — 왜 안 넣었는지가 감사 대상이다.

## 3. 충돌 판정 규칙

### 방향은 항상 "신규 레코드 기준"

> 기존: **프랑스** TV 안전 규제가 이미 등록돼 있다
> 신규: **유럽** TV 안전 규제를 등록한다
> → 신규(유럽) ⊃ 기존(프랑스) → **`PARENT`** (신규가 기존의 상위)

반대로 유럽이 먼저 있고 프랑스를 새로 넣으면 `CHILD` 다. 같은 상황을 두 코드로 나눠 기록하는 이유는,
**나중에 목록에서 "이 레코드가 누구의 하위인가"를 방향 그대로 읽어야 하기 때문**이다.

| 유형 | 조건 | 권고 조치 |
|---|---|---|
| `SAME` | 모든 축이 동일 | 신규 등록 말고 기존을 개정(REPLACE) |
| `PARENT` | 신규 ⊇ 기존 (한 축 이상 진부분집합) | 기존을 하위 예외로 유지(KEEP_BOTH) 또는 신규에서 제외(EXCLUDE) |
| `CHILD` | 신규 ⊆ 기존 | 신규를 기존의 하위 예외로 등록(KEEP_BOTH) |
| `OVERLAP` | 포함관계 없이 일부만 겹침 | 겹치는 대상을 한쪽에서 제외(EXCLUDE) |

### 판정 알고리즘 (`regulationConflict.js`)

1. **1차 필터** — 분야(`FIELD_CD`)가 다르면 충돌 아님. 폐지(`EXPIRED`) 레코드도 제외.
2. **leaf 전개** — 계층이 다른 값을 그대로 비교할 수 없으므로 최하위 단위 집합으로 편다.
   - `유럽` → `{FR, DE, IT, ES, PL}`, `유럽 > 프랑스` → `{FR}`
   - 하위 타입이 선택돼 있으면 그게 우선(더 좁은 범위), 아무것도 없으면 `전체`
3. **축별 관계** — GEO / ORG / RULE 각각 `EQUAL · SUPERSET · SUBSET · OVERLAP · DISJOINT`
4. **합성** — 한 축이라도 `DISJOINT` 면 충돌 아님(한국 규제 vs 유럽 규제는 서로 무관).
   전부 EQUAL → `SAME`, EQUAL+SUPERSET → `PARENT`, EQUAL+SUBSET → `CHILD`, 그 외 → `OVERLAP`

### 조치별 실제 처리

| DECISION_CD | 처리 |
|---|---|
| `KEEP_BOTH` | 둘 다 살린다. 기존에 `PARENT_INFO_ID` 를 걸고 `CONFLICT_RESOLVE` 이력 남김 |
| `MERGE` | 기존을 `EXPIRED` 로 내리고 신규가 대체 |
| `EXCLUDE` | 신규 타겟에 기존 대상을 `EXCLUDE_YN='Y'` 로 추가 ("유럽 전체, 프랑스 제외") |
| `REPLACE` | 신규를 만들지 않고 기존의 새 버전으로 저장 |
| `CANCEL` | 저장 안 함. 충돌 이력만 `IGNORED` 로 남김 |

## 4. 화면

### 4-1. 구성

```
[1] 검색 그리드 (조회 조건 폼)
    키워드 · 분야 · 권역 · 국가 · 규제 · 사업부 · 제품군 · 제품 · 상태 · 시행일 기간 · 충돌만 보기
    - 권역을 고르면 국가 옵션이, 사업부를 고르면 제품군/제품 옵션이 따라 좁혀진다

[2] 리얼그리드 (정보 레코드 목록)
    상태 | 규제번호 | 규제명 | 규격 | 분야 | 인증마크
    [적용 제품: 사업부·제품군·제품] [적용 지역: 권역·국가]  ← 컬럼 그룹
    URL(링크) | 첨부 | 충돌 | 버전 | 시행일 | 최종수정일
    - 멀티값은 "유럽 외 2" 로 축약, 행 더블클릭 = 수정
```

### 4-2. 저장 흐름 — 충돌 검사는 저장 "직전"에

```
[등록/수정 모달]  멀티셀렉트 7종 입력
      │
      │ "충돌 검사 후 저장" 클릭
      ▼
detectConflicts(신규, 기존목록)
      │
      ├─ 충돌 0건 ─────────────────────────► 즉시 저장 + HIST INSERT
      │
      └─ 충돌 N건 ► [충돌 확인 모달]
                     · 유형 배지 + 충돌 축
                     · 기존 범위 / 신규 범위를 축별로 나란히
                     · 행마다 조치 select (권고값 기본 선택)
                     ├─ 돌아가서 수정
                     ├─ 등록 취소 → CONFLICT_HIST(IGNORED) 만 남김
                     └─ 조치 반영 후 저장
                          → REG_INFO(+TARGET) 저장
                          → REG_INFO_HIST INSERT (새 버전)
                          → REG_CONFLICT_HIST INSERT (조치 포함)
                          → 조치별 기존 레코드 후처리(MERGE면 EXPIRED 등)
```

**왜 저장 직전인가**: 입력 도중에 검사하면 아직 범위가 덜 채워진 상태라 오탐이 쏟아진다.
멀티셀렉트를 다 채운 시점 = 범위가 확정된 시점이라 그때 한 번만 돈다.

### 4-3. 이력 모달
선택 레코드의 **변경 이력**(버전·구분·사유·변경자)과 **충돌 이력**(유형·상대 레코드·범위 비교·조치)을 탭으로 분리.

### 4-4. 데모
등록 모달 우상단 **"충돌 시나리오 채우기"** 버튼 → 신규 "유럽 공통 LVD" 를 채운다.
저장하면 기존 `REG-2025-0087` (프랑스 특례)와 **PARENT** 충돌이 잡히는 걸 바로 볼 수 있다.

## 5. 남은 논의거리

- **조회 성능**: 목록에서 멀티값 7종을 `LISTAGG` 서브쿼리로 뽑고 있다. 건수가 커지면
  `REG_INFO` 에 표시용 비정규화 컬럼(`REGION_TXT` 등)을 두고 저장 시 갱신하는 편이 낫다.
- **충돌 검사 범위**: 지금은 같은 분야 전체를 훑는다. 레코드가 수천 건이 되면
  DDL 하단 주석의 1차 필터 쿼리(같은 분야 + 같은 규제 공유)로 후보를 줄이고 앱에서 판정.
- **권역-국가 마스터**: 지금은 화면 mock 코드다. 공통코드 관리(`/system/common-codes`)로 옮겨야
  "EU 회원국 변경" 같은 사건에 데이터만 고쳐도 판정이 따라온다.
- **EXCLUDE 표현**: `EXCLUDE_YN` 으로 "유럽 전체, 프랑스 제외"는 되지만,
  화면 UI(멀티셀렉트에 제외 배지)는 아직 미구현.
